# claude-supervisor 核心监督能力短周期实施计划

> **For agentic workers:** 本次用户要求修订计划，未要求立即执行新计划。后续获准实施时，使用 `superpowers:executing-plans` 逐任务推进；每项先验证失败用例，再实现和检查，用 checkbox 记录结果。拟新增能力不能写成已实现能力。

**Goal:** 优先验证旁路能否补齐关键定位事实、提供有效复现，使主模型少走错误路径、修好更多任务；用小批次结果决定下一步投入。

**Architecture:** 主模型继续负责需求解释、方案选择和真实代码修改。旁路每次只补一项缺失信息：入口/调用事实，或区分假设的复现/反例；程序核对来源、版本和预算后交给主模型。复用现有 coordinator、ledger、runner 和 hook，首轮不建设完整的新监督框架。

**Tech Stack:** 现有 TypeScript / Claude Code hooks/testing、Node.js 22、Node 离线评测。只读文件检查不依赖沙盒；已有 macOS 执行器可用于副本验证，Linux 独立执行支持另行验证。

## Global Constraints

- 旁路强弱关系不限，默认使用当前主模型；不通过模型 ID 认证排序，不依赖更强备用模型。
- 顶级参考模型只用于离线对照，首轮不要求运行；没有参考结果不宣称接近顶级模型。
- 旁路不修改真实工作区。文件读取采用受限路径和脱敏；项目代码只在通过能力验证的沙盒执行。不能隔离时，由主模型在原授权范围内决定是否执行建议。
- 需求解释、期望值和修复方案不是旁路的裁决权。模型提出的测试即使运行失败，仍须区分真实观察与语义假设。
- 所有新增旁路工作共享每用户提示最多 2 次模型调用、4,000 输出 tokens、30 秒活动预算；格式重试也占额度。额度不足就停止，不以新模式重置预算。
- 保留现有规则和 on/off/auto；新增能力默认关闭。新旧模型流程共享预算且只选择一个流程，不并行重复审查。
- 结果只用于对应任务及所读文件版本；新提示、off、取消、文件变化后的旧反馈丢弃。来源缺失、输出截断、环境失败记 unknown。
- 功能成功、诚实报告、约束遵守分别统计。缺失费用记 unknown，不能用 token 上限或估算费用宣称总成本优势。
- 当前主要环境为 CentOS 7、Node 22、无 Docker，实际内核未知。按实际能力探测，不根据发行版或模型名称阻止只读辅助。

## Review Focus

1. 同名函数、动态入口、生成文件：提供真实调用证据，不能只猜文件名（任务 1）。
2. 不存在的引用、秘密或越界路径、文件中途改变：拒绝该信息包（任务 1）。
3. 错误期望值、范围外输入、导入失败：不把运行失败认证为缺陷（任务 2）。
4. 用户取消、旧反馈迟到、预算不足：不继续调用、不投递到新任务（任务 1–2）。
5. 简单任务、无新证据的恢复：允许无介入，记录额外开销（任务 0、3）。

## 1. 调研结论怎样变成能力

调研给出的是可检验方向，尚无本项目弱主模型与顶级模型的配对轨迹实测；下表不是已确认的通用强弱模型排序。

| 调研中的执行差异 | 监督应新增什么 | 交付顺序与短期验收 |
|---|---|---|
| 找错入口、漏调用者、API 用错 | **定位事实补齐**：实际入口、调用位置、局部 API 约定及原文出处 | **第一轮，任务 1。** 主模型依据事实改正定位，独立验收通过 |
| 读很多文件仍没有有效信息，反复支持原假设 | **有效实验**：区分原因、或覆盖明确需求边界的复现/反例 | **第二轮，任务 2。** 记录排除了什么、主模型改变了什么动作 |
| 看见失败仍盲改、反复重跑 | **失败恢复**：已确认事实、已排除假设和一个待验证问题 | **第三轮，任务 3。** 减少无效重试，无新增证据即停 |
| 漏需求或误读边界 | 每个信息包引用相关用户要求；歧义标明，复现边界有来源 | 并入任务 1–2；完整需求登记和长会话摘要延后 |
| 跨文件不一致、错误方案 | 用真实调用者和行为反例暴露具体冲突，由主模型决定方案 | 并入任务 1–2；不建设通用架构 reviewer 或多候选裁判 |
| 虚报通过、提前结束 | 已有证据核验、范围对应和评分拆分 | 复用已有 P0；只修复阻碍当前试验的缺口 |

选择“定位 → 实验 → 恢复”，因为前两项直接提供主模型缺少的事实，容易观察是否改变执行路径。完整上下文治理、自动调度和工程恢复的收益链更长，后移。三项分别验收，不同时开启再用一个最终分数判断。

## 2. 第一轮究竟交付什么

首轮只有任务 0 和任务 1，目标在 **2–3 个工作日内得到一次小规模筛查结果**；这是时间盒，不是收益承诺。超过时间盒先交付可回放的信息包和具体阻碍，不继续扩大框架。

- 输入例：主模型准备修改 `util.cjs` 的 `parseDate`，但 `app.cjs` 实际引用 `utils.cjs`。
- 旁路输出例：实际导入行和被调用实现的出处，外加尚未验证的解释；不代写修复。
- 主模型应有的变化：重新定位、修改真实实现，运行原测试及独立验收。
- 首轮报告展示这条完整轨迹，同时保留无收益、错误建议和简单任务的情况。

先不实现 Linux 沙盒也能交付这一轮：旁路只读受限文件，执行和修改仍由主模型完成。

| 拟新增文件 | 时点 | 责任 |
|---|---|---|
| `supervisor/assist.ts`、`tests/assist.test.ts` | 任务 1 | 窄任务协议、引用核对、主模型信息包 |
| `scripts/selftest-assist.mjs` | 任务 1 | 真文件只读边界检查，无模型费用 |
| `supervisor/probes.ts`、`tests/probes.test.ts` | 任务 2 | 复现候选及观察/语义分离 |

| `eval/tasks-assist.mjs`、`eval/selftest-assist.mjs` | 任务 0 | 小型目标任务及评分自检 |
| `docs/evals/2026-10-12-core-assistance-pilot.md` | 任务 0 起 | 冻结配置、逐轮效果、失败案例与决定 |

新增 `assistance_mode: existing | facts | probe | recovery`，默认 `existing`。各值分别选择旧模型流程或一项窄任务流程，不叠加三套模型循环；确定性规则在各模式保留。`execution_mode` 继续只控制独立执行，不隐含允许读写真实目录。

拟定共用类型：

```ts
type SourceFact = { id: string; path: string; startLine: number; quote: string; fileHash: string }
type FactRequest = { paths: string[]; terms: string[]; searchPaths?: string[] }
type FactView = { facts: SourceFact[]; manifestHash: string; incomplete: boolean; searchScope?: { paths: string[]; terms: string[] } }
type AssistInput = { binding: Binding; asked: string; recentFacts: SourceFact[]; symptom: string }
type AssistPacket = {
  binding: Binding; kind: 'location' | 'probe' | 'recovery'; question: string
  requirementQuote: string; factIds: string[]; observationIds: string[]
  explanation: string; nextCheck: string | null; requiresMainJudgment: true
}
```

`inspectFacts(request: FactRequest, deadlineMs: number): Promise<FactView>` 加入 Host 端口，以 `scripts/supervisor-host.mjs` 的新 `inspect` action 实现，只查文件，不执行项目代码。`parseFactRequest(text): FactRequest | null`、`buildAssistPacket(input, view, text): AssistPacket | null` 在 `assist.ts`；发送仍走 coordinator。信息包是辅助事实和假设，不是证明项目正确的 Issue。
