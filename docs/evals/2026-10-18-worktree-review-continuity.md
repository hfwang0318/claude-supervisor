The plugin treated every `session.cwd()` change as a new project generation. The canceled reservation was correctly retained, but the ordinary navigation reduced the available review opportunities. This batch repairs that identity mismatch without refunding or replaying the earlier call.

Only incremental advisory scheduling changes. The trusted local service performs a bounded read-only lookup through `/usr/bin/git`, returning canonical worktree root and Git-directory paths. It ignores ambient `GIT_*` overrides and disables filesystem-monitor configuration. A project-provided executable on `PATH` cannot supply the identity. No shell or candidate command runs. If system Git is unavailable, the location is not a working tree, or the lookup fails, identity stays unknown.

The plugin caches the result for the currently observed directory. A directory change requires a new lookup. Historical advice stays in the same task only when both identities are known and equal. A nested repository, separate repository or linked worktree has a different identity; an unknown result also preserves the existing cancellation behavior. Concurrent callbacks share the lookup, and a second cwd change during resolution invalidates conservatively instead of pairing one directory's proof with another.

Execution cwd remains separate from task identity. A historical report may survive navigation, but supplemental source inspection or independent actions still require the captured cwd and source binding. Unknown or changed source falls back to historical prose. Task/model changes, explicit cancellation and reload retain their existing gates.
